# HoyoPlay Gacha Tracker / 米游抽卡统计

绝区零（Zenless Zone Zero）与原神（Genshin Impact）抽卡记录统计与可视化桌面工具，基于 Electron + React 构建，数据完全本地存储。

## 功能特性

- **双游戏支持**：绝区零 / 原神一键切换，独立数据管理
- **卡池动态展示**：饼图卡片完全由数据驱动，账号有记录的卡池才显示（含集录祈愿、新手祈愿等全部已知卡池；原神双角色池 400 自动并入角色活动祈愿统计）：
  - 绝区零：独家频段、音擎频段、常驻频段、邦布频段
  - 原神：角色活动祈愿、武器活动祈愿、常驻祈愿、集录祈愿、新手祈愿
- **环形图可视化**：各卡池最高稀有度出率一目了然
- **时间线记录**：按时间轴展示获取记录，标注抽数间隔
- **保底计数**：实时显示当前保底进度，渐变色直观提示
- **保底类型判断**：自动识别小保底 / 大保底状态
- **捕获明光概率**：原神小保底时显示捕获明光触发概率（基于社区统计模型）
- **多账号管理**：支持多 UID 切换浏览
- **增量同步**：仅拉取新增记录，避免重复请求
- **一键导出**：将时间线导出为 1080×1920 分享图片
- **图标自动获取**：从米哈游 Wiki API 拉取物品图标

## 环境要求

- Windows 操作系统
- Node.js >= 18
- npm >= 9
- 绝区零或原神游戏客户端（用于读取日志提取 authkey）

## 安装与运行

```bash
# 克隆仓库
git clone https://github.com/Aimang2002/hoyoplay-gacha-tracker.git
cd hoyoplay-gacha-tracker

# 安装依赖
npm install

# 启动开发环境
npm run dev

# 构建 Windows 版本
npm run build:win
```

## 使用方法

1. 启动游戏客户端（绝区零或原神）
2. 在游戏内打开抽卡历史记录页面（生成 authkey）
3. 在工具界面选择对应游戏，点击「同步数据」按钮
4. 等待数据拉取完成，即可查看统计信息

## 数据存储

所有数据保存在本地 `data/gacha.db`（SQLite），首次运行时自动创建，不会上传至任何服务器。

## 卡池类型 ID 对照

官方 API 只返回数字 `gacha_type`（无卡池名称），名称映射由本工具维护：

| 游戏 | ID | 卡池 | 说明 |
|------|----|------|------|
| 原神 | 200 | 常驻祈愿 | |
| 原神 | 301 | 角色活动祈愿 | 统计时自动聚合 400 |
| 原神 | 302 | 武器活动祈愿 | |
| 原神 | 400 | 角色活动祈愿-2 | 双角色池，与 301 共享保底；直查为空，仅在 301 查询结果中合并返回 |
| 原神 | 500 | 集录祈愿 | 有记录才显示（动态展示） |
| 原神 | 100 | 新手祈愿 | 有记录才显示（动态展示） |
| 绝区零 | 1 | 常驻频段 | |
| 绝区零 | 2 | 独家频段 | |
| 绝区零 | 3 | 音擎频段 | |
| 绝区零 | 5 | 邦布频段 | S级必为所选UP，无大小保底概念 |

大小保底标签按池判定：仅限有 UP 概念的卡池（角色/武器/独家/音擎），常驻池不显示（无 UP 概念）。集录祈愿为「定轨 + 命定值」机制，定轨物品不在抽卡记录 API 中，无法从数据直接判定——仅当命定值必然已清零时（从未出五星 / 最新五星距今超过一个卡池周期约 21 天）显示小保底，否则不显示。武器活动祈愿的命定值同样只在当期有效：歪了之后若距当次五星超过约 21 天（卡池必然已轮换），则降级显示小保底。武器活动祈愿保底上限为 80 抽；绝区零音擎频段 80 抽、邦布频段 80 抽（邦布 S 级必为所选 UP，无大小保底概念）。

## 捕获明光概率模型

原神 5.0 版本（2024 年 8 月 28 日起）引入了「捕获明光」机制：小保底歪了之后，下次小保底不歪的概率会提升。连歪次数越多，捕获明光触发概率越高。

本工具使用的概率模型来自社区统计：

| 连歪次数 | 捕获明光概率 |
|----------|-------------|
| 1 | 4.55% |
| 2 | 45.45% |
| 3 | 100% |

**数据来源**：[知乎 - 原神5.0捕获明光机制讨论](https://www.zhihu.com/question/664442510)
